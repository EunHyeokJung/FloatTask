# 2) Specs

## Runtime

- 플랫폼: macOS 14+
- 언어: Swift 5 언어 모드, Swift 6.1 툴체인
- UI: SwiftUI + AppKit
- 배포: 의존성 없는 `.app` 번들
- 저장: Codable JSON, 임시 파일 기반 원자적 교체, 프로세스 간 파일 잠금

## UI 규칙

- 메인 패널 기본 크기: 360 × 500pt. 테두리/모서리 드래그로 가로·세로 크기를 조절할 수 있으며 최소 크기는 320 × 280pt입니다. 시스템 titlebar와 별도 크기 조절 아이콘은 추가하지 않습니다.
- 메인 창 위치와 크기를 함께 기억합니다. 내용 영역은 창을 채우고, Task 말줄임/펼침은 변경된 실제 가용 폭을 사용합니다. 창 크기 조절 자체에는 추가 애니메이션을 적용하지 않습니다.
- 메인 크기 변경 시 열려 있는 채팅·완료·Settings의 콘텐츠와 크기를 유지한 채 화면의 빈 옆 공간으로 다시 배치합니다. 보조 패널은 기존 기본 크기를 유지하며 메인 높이를 상속하지 않습니다.
- 시스템 titlebar를 창 스타일에서 제거하고 전체 영역을 하나의 material과 표면색으로 합성합니다.
- 메인 패널은 SwiftUI 기본 Window가 아닌 전용 `NSWindow`를 사용하며 `canBecomeKey`와 `canBecomeMain`을 항상 보장합니다.
- 비활성 앱을 클릭한 첫 이벤트에서 앱 활성화와 키 윈도 전환을 먼저 수행하고, hosting view가 first mouse를 수용해 같은 클릭을 입력 필드에 전달합니다.
- 시스템 폰트와 SF Symbols만 사용합니다.
- 앱 아이콘은 짙은 차콜 패널, 흰색 작업 원형과 작업선, system blue 체크로 구성하며 텍스트와 장식용 상태 표시는 사용하지 않습니다.
- 1024px 원본에서 macOS 표준 16·32·64·128·256·512·1024px 자산을 생성해 `FloatTask.icns`로 번들링합니다.
- 4/8pt 간격 체계와 의미 기반 색상 토큰을 사용합니다.
- 주요 모션은 150–300ms 범위의 스프링으로 제한합니다.
- `accessibilityReduceMotion` 활성화 시 즉시 전환에 가깝게 축소합니다.
- 버튼의 최소 클릭 영역은 32pt, 핵심 체크 컨트롤은 36pt 이상입니다.
- 보이는 문구는 프로젝트명과 작업명 중심으로 제한합니다.
- 앱의 고정 UI 문구와 접근성 레이블은 영어를 사용하며 봇 답변 언어와 분리합니다. 사용자 프로젝트명·Task 제목·입력 메시지는 번역하거나 수정하지 않습니다. 날짜는 영어 약식으로 표시하며 전체 시각은 툴팁으로 제공합니다.
- 헤더 왼쪽은 고정 버튼이며, 오른쪽은 채팅·프로젝트 추가·완료 목록·설정·닫기 순서로 배치합니다. 고정 아이콘은 실제 항상 위 설정을 반영합니다.
- 기본 프로젝트 목록은 미완료 Task만 표시합니다. 완료 시 행이 부드럽게 사라지며 프로젝트명 오른쪽에 체크 원 아이콘과 실제 완료 개수만 표시합니다. 0개일 때는 개수를 숨기고, 모든 Task가 완료되어도 프로젝트 헤더는 유지합니다.
- 헤더 체크 버튼은 전체 완료 목록 패널을 열고 닫습니다. `⌘⇧C`는 전체 목록을 열며 프로젝트의 완료 개수를 누르면 같은 패널에서 해당 프로젝트로 필터링합니다. 열린 패널은 재사용하며 패널 헤더의 닫기·Escape로 닫을 수 있습니다.
- 완료 패널은 한 줄의 48pt 헤더에 체크 원 아이콘·실제 개수·프로젝트 필터·정렬·닫기만 표시하며 완료 제목은 반복하지 않습니다. 프로젝트 필터는 `All projects` 또는 선택된 프로젝트명인 텍스트 버튼, 정렬은 아이콘 버튼으로 표시하며 기본 Picker/select 외형을 사용하지 않습니다. 선택 목록은 동일 스타일의 커스텀 팝오버로 열고 선택 표시·방향키·Enter·Escape를 지원합니다.
- 정렬 선택은 `Recently completed`(completedAt 내림차순, 기본)·`Date added`(createdAt 오름차순)을 제공합니다. 완료 시각이 없는 기존 항목은 최근 완료순에서 마지막에 배치하고 날짜 대신 대시·툴팁으로 구분합니다. 동일 시각은 ID로 정렬을 안정화합니다.
- 완료 행은 제목 아래 프로젝트와 날짜를 한 줄에 배치합니다. `Completed`·`Added` 접두어와 전체 시각은 화면에 반복하지 않고 툴팁/접근성 정보로 제공합니다.
- 완료 목록에서 체크 버튼을 누르면 Task를 재개하여 기본 목록으로 복원합니다. 목록·필터·완료 개수는 앱과 CLI의 변경을 실시간 반영하며, 저장은 기존 TaskViewModel과 TaskFileStore.update를 사용합니다.
- 완료 목록은 채팅과 같은 336 × 500pt borderless 자식 패널입니다. material 표면, 18pt 모서리, 48pt 내부 헤더, 메인 패널 옆 8pt 간격과 열기 280ms·닫기 170ms 모션을 공유하며 시스템 titlebar는 표시하지 않습니다. 메인 창의 이동·항상 위·Space 정책을 따릅니다. 모션 감소 시 패널 이동 애니메이션은 생략하고 행 전환을 즉시 전환에 가깝게 축소합니다.
- 채팅과 완료 목록은 동시에 열 수 있으며 열기·닫기 상태를 독립적으로 유지합니다. 먼저 열린 패널을 이동하거나 닫지 않고, 새 패널은 왼쪽의 빈 자리에 8pt 간격으로 추가합니다. 왼쪽 공간이 부족하면 오른쪽의 빈 자리를 사용합니다. 화면 공간이 허용되는 범위에서 메인/다른 패널과 겹치지 않도록 배치하며 채팅 세션은 보존합니다.
- borderless 창의 드래그 영역은 상단 툴바의 빈 공간으로 제한해 이름 입력 필드의 클릭·커서·선택 동작과 충돌하지 않게 합니다.
- 프로젝트명과 작업명 입력은 레이아웃을 바꾸지 않는 1pt 하단선으로 포커스를 표시하고 Enter 또는 포커스 이탈 시 저장합니다. 기존 작업과 새 작업 입력은 편집 전·중·후 동일한 텍스트 시작점을 유지합니다.
- Task 제목은 비편집 상태에서 기본 한 줄로 유지하고 단어 경계에서 끝 말줄임표로 표시합니다. 말줄임표가 표시되는 Task에 Hover하면 동일한 가용 너비와 단어 줄바꿈 규칙을 유지한 채 줄 수 제한만 해제해 행을 아래로 부드럽게 확장합니다. 텍스트 레이아웃은 확장 완료 높이를 사용하고 표시 영역만 현재 행 높이로 잘라 매 프레임 드러냅니다. 현재 애니메이션 높이를 텍스트 레이아웃 높이로 사용하지 않아 다음 줄 전체가 들어갈 때까지 기다리는 지연을 방지합니다. 접힘·펼침 사이에 첫 줄의 기존 단어가 이동하지 않으며 편집 상태에서도 전체 제목을 확인할 수 있습니다.
- 프로젝트 추가 버튼이나 `⌘⇧N`으로 프로젝트를 생성하면 새 `Project` 이름 전체를 선택하고 즉시 입력 포커스를 이동합니다.
- 더보기·컨텍스트 메뉴, 삭제 확인 대화상자, 컨트롤 툴팁은 간결한 영어 문구를 사용합니다.
- 기존 작업명을 편집한 뒤 Enter를 누르면 변경 내용을 저장하고 해당 작업 바로 아래에 새 작업 입력을 생성해 자동으로 포커스합니다. 새 작업에서 Enter를 연속 입력하면 방금 생성한 작업 다음 위치로 입력 행을 이동합니다.
- Task 행의 삭제 버튼 영역은 항상 동일한 너비를 예약하고 Hover·포커스 상태에서는 투명도와 상호작용만 전환합니다. Enter 처리에서는 제목을 먼저 저장한 뒤 포커스와 새 입력 행을 변경해 기존 제목 상태를 보존합니다.
- 창은 현재 필드 밖의 마우스 클릭과 다른 창으로의 전환을 감지해 편집 포커스를 명시적으로 해제합니다. 새 작업 입력은 포커스 이탈 시 내용이 있으면 저장하고, 비어 있으면 닫습니다.
- 프로젝트 메뉴와 작업 컨텍스트 메뉴도 명시적인 `Rename` 진입점을 제공합니다.
- 핀 상태는 앱 정책까지 전환합니다: 항상 위는 `.accessory` + 모든 Space, 일반 창은 `.regular` + Mission Control 관리 대상입니다.
- 번들 자체는 일반 앱으로 등록하고, 항상 위 모드에서만 런타임 activation policy를 `.accessory`로 전환합니다.
- 채팅은 메인 창 왼쪽 바깥에 붙는 별도 자식 패널이며, 화면 왼쪽 공간이 부족할 때는 오른쪽에 배치합니다. 열기 280ms·닫기 170ms로 이동과 투명도를 함께 보간합니다.
- 채팅 패널은 메인 창의 이동, 창 레벨, Space 정책을 따르며 메인 창의 크기나 클릭 영역을 바꾸지 않습니다.
- 채팅 입력 영역은 패널 하단에 고정하고 대화 목록이 위쪽의 남은 영역을 확장해 채우게 합니다. 여러 줄 입력 텍스트는 입력 영역 내부 상단에 정렬합니다.
- 채팅 헤더의 에이전트 아바타는 Bloub의 상태 언어를 따릅니다. 대기 시 눈동자와 눈깜빡임, 추론 시 `Thinking`, 명령 실행·파일 변경·응답 적용 시 `Comet`, 실제 MCP·웹 검색 시에만 `Wide Eyes`를 표시합니다.
- 에이전트 상태는 `codex exec --json`의 JSONL 이벤트에서 결정하며 장식용 가짜 실행·연결 상태를 만들지 않습니다.
- 아바타는 SwiftUI `Canvas`를 30fps로 그리며 상태 전환은 200ms ease-out을 사용합니다. 모션 감소가 켜지면 각 상태의 정지 프레임만 표시합니다.

## Settings

- 메인 헤더와 채팅 리셋 옆의 설정 아이콘, 앱 메뉴의 `Settings…`, `⌘,`는 하나의 Settings 패널을 엽니다. 이미 열린 창은 재사용하며 채팅·완료 패널을 닫지 않습니다.
- Settings는 기존 material·18pt 모서리·48pt 헤더를 공유하는 336 × 252pt의 작은 borderless 패널입니다. 헤더에는 `Settings`와 닫기만, 본문에는 세 가지 설정만 표시합니다. Escape와 닫기 버튼을 지원합니다.
- `Show in menu bar`: macOS 메뉴 막대에 템플릿 체크 원 아이콘을 표시하며 기본값은 꺼짐입니다. 변경 즉시 아이콘을 추가/제거합니다. 아이콘을 클릭하면 드롭다운 메뉴 없이 메인 Task 창을 즉시 표시/숨김 전환합니다. Settings를 자동으로 열거나 앱을 종료하지 않습니다.
- 메뉴 막대로 숨길 때 현재 열린 보조 패널도 함께 숨기며, 다시 표시할 때 기존 패널·대화·채팅 입력·창 위치/크기를 그대로 복원합니다. 숨김과 창 닫기/앱 종료를 분리합니다. 기존 메인 X 버튼의 앱 종료 동작은 유지하며 Settings는 창 안의 gear 또는 `⌘,`로 엽니다.
- 마지막 창이 화면에서 사라져도 앱을 자동 종료하지 않습니다. 메뉴 막대 숨김 후에도 프로세스와 아이콘을 유지하며, 일반/항상 위 모드 모두 AppKit 이벤트 루프에서 숨김·복원 반복 시 종료 요청이 발생하지 않아야 합니다. 명시적인 X·Quit 종료는 유지합니다.
- `Keep on top`: 기존 핀 동작과 같은 단일 상태를 사용합니다. 어느 쪽에서 변경하든 핀 아이콘·창 레벨·Space 정책과 Settings 스위치가 즉시 일치합니다.
- `Reply language`: 기존 Korean / English 선택을 통합합니다. 값과 chevron만 표시하는 커스텀 선택 메뉴를 사용하며 native select는 사용하지 않습니다.
- 모든 설정은 변경 즉시 UserDefaults에 저장하며 별도 Save 버튼은 없습니다. 기존 항상 위·답변 언어 키를 보존하고 Task 데이터 스키마는 변경하지 않습니다. 자동 실행·테마·모델·연동 등 사용하지 않는 옵션은 추가하지 않습니다.

## Data contract

- `TaskDatabase.schemaVersion`: 현재 `1`
- `TaskDatabase.revision`: 모든 쓰기마다 증가
- 프로젝트와 작업 ID: UUID 문자열
- 날짜: ISO-8601
- 앱과 CLI는 동일 파일을 감시하며 외부 변경을 자동 반영합니다.

## Google Tasks

- Google Tasks REST API v1을 사용합니다.
- OAuth access token은 저장하지 않고 명령 실행 시 전달하거나 `GOOGLE_TASKS_ACCESS_TOKEN` 환경 변수로 받습니다.
- `google sync`는 Google 목록/작업과 로컬 데이터를 ID 기준으로 병합합니다.
- 충돌 시 작업의 `updated` 시각이 더 최신인 쪽을 반영합니다.
- 원격 삭제 전파는 데이터 손실 방지를 위해 MVP에서 제외합니다.

## Codex chat

- 로컬 Codex CLI의 비대화형 `codex exec`를 사용합니다.
- `--json` 이벤트 스트림에서 reasoning, command/file/plan/answer, MCP/web 이벤트를 구분해 UI 상태에 전달합니다.
- 모델은 `gpt-5.6-luna`, reasoning effort는 `xhigh`로 고정합니다.
- 채팅 헤더의 리셋 버튼과 닫기 버튼 사이에 설정 아이콘을 배치합니다. 메인과 같은 Settings 패널에서 `Reply language`를 `Korean` / `English`로 선택하며 기본값은 Korean입니다.
- 답변 언어는 UserDefaults의 UI 설정으로 저장해 패널 닫기·채팅 초기화·앱 재실행 후에도 유지합니다. Task JSON 스키마에는 추가하지 않습니다.
- 전송 시 답변 언어를 요청에 고정하여 모델 지시문, 검증·저장된 액션 결과, 빈 응답 및 중지 문구에 동일하게 적용합니다. 설정 변경은 이후 전송부터 적용하며 진행 중 응답과 기존 대화 기록을 다시 번역하지 않습니다. 앱 오류·컨트롤 레이블은 영어로 유지합니다.
- 실행은 read-only sandbox, ephemeral session, 사용자 설정 및 저장소 규칙 비활성화 상태로 격리합니다.
- 현재 프로젝트/작업과 최근 대화 최대 16개만 최대 길이를 제한해 전달합니다.
- 모델 출력은 JSON Schema로 제한하고, 앱이 ID·필수 필드·문자 수·삭제 의도를 다시 검증합니다.
- 검증된 변경 전체를 한 번의 파일 잠금과 원자적 쓰기로 적용하며 중간 실패 시 어떤 변경도 저장하지 않습니다.
- 요청 제한 시간은 120초이며 인증, 모델, 한도, 네트워크 오류를 사용자에게 구분해 표시합니다.
- 응답 생성 중 전송 버튼은 중지 버튼으로 전환하며, 중지 시 실행 중인 Codex 프로세스까지 종료하고 임시 파일을 정리합니다.
- 채팅 초기화는 실행 중인 응답을 중지하고 대화 기록과 후속 문맥만 비우며 프로젝트·작업 데이터는 유지합니다.
- 변경 요청에서는 제안·계획 문구를 표시하지 않고, 앱이 검증하고 저장한 변경 결과만 응답합니다.

## CLI 안정성

- 자동화는 `--json` 출력을 우선 사용합니다.
- ID는 전체 UUID 또는 충돌하지 않는 접두어를 허용합니다.
- 실패는 stderr와 0이 아닌 종료 코드로 전달합니다.

## 빌드와 검증

- 단위·통합 테스트: `swift test`
- release 앱과 CLI 생성: `./scripts/build-app.sh`
- 앱 서명 확인: `codesign --verify --deep --strict dist/FloatTask.app`
- UI 변경은 사용자 데이터와 분리된 `FLOATTASK_DATA_FILE` 저장소에서 실제 렌더링과 접근성 트리를 확인합니다.
- 구조·스펙·제품 범위가 구현과 다르면 코드 변경 전에 해당 문서를 먼저 갱신합니다.
